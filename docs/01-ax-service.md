# .ax 서비스 정의서

> 상태: 초안 v0.3 · 핵심 문제를 "비용"에서 **"확장성"**으로 재정의 · 가격은 **더미 숫자**

## 1. 한 줄 정의

**범용 SaaS의 한계에 부딪힌 성장 기업을 위해, 우리 사업 방식대로 시스템을 다시 짓고 그 안에서 AI가 실제 업무를 맡게 하는 구독형 AX 전환 서비스.**

> 사업이 커지면, SaaS가 좁아집니다.

- 개발비와 유지보수를 따로 팔지 않는다. 고객은 **.ax 하나를 계약**한다.
- 약정 기간이 끝나면 **소스코드와 시스템 소유권은 고객사에 이전**된다.

## 2. 왜 지금인가 (피봇 논리)

**성장 기업이 범용 SaaS에서 겪는 문제 = 확장성**

- **안 맞는 기능:** 메뉴 절반은 우리 사업과 무관하다. 그래도 그 구조에 맞춰 일한다
- **없는 기능:** 도매 거래처별 단가, 공동구매 정산, 맞춤 제작 주문처럼 사업에 꼭 필요한 업무는 메뉴에 없다 → 엑셀·수작업·외부 플러그인으로 덧댄다
- **끊긴 데이터:** 쇼핑몰·CRM·ERP SaaS를 이어 붙여 데이터가 흩어진다
- **막힌 AI:** 데이터가 흩어지고 업무 흐름을 바꿀 수 없으니, 플랫폼이 주는 AI 기능 외에는 쓸 수 없다
- 결국 **회사가 SaaS에 맞춰 일하고, 사업 방식이 플랫폼의 한계에 갇힌다**

| 과거 | 지금 |
|---|---|
| 자체 시스템은 구축이 길고 비싸서, 성장 기업도 SaaS를 참고 썼다 | AI로 구축 기간이 크게 줄어, 사업에 맞는 시스템을 빠르게 지을 수 있다 |
| 시스템은 한 번 만들면 끝 | 사업이 커지는 속도에 맞춰 **계속 확장**하는 구독형 개발이 가능하다 |

## 3. 네이밍

- 서비스 패밀리명: **`.ax`** (읽기: 닷에이엑스) — 회사 로고 `.mate`와 같은 문법, 빨간 점 공유
- 라인업: **`.ax commerce`** · **`.ax erp`** · **`.ax crm`** · **`.ax edu`**
- 표기 규칙: 점은 항상 레드, 나머지는 소문자 검정. 문장 속 텍스트로는 "닷AX 커머스"처럼 읽기 표기 병기
- 브랜드 위계: **.mate**(회사) → **.ax**(서비스) → **.ax crm**(라인업)

## 3-1. 타겟

- **대상:** 범용 SaaS의 한계에 부딪힌 **성장 단계 기업** (월 이용료는 부담이 아님)
- **1차 영업 타겟:** 아래 4개 분야

| 라인업 | 대체 대상 (예시) | AX로 바뀌는 업무 (예시) |
|---|---|---|
| **.ax commerce** | 국내외 쇼핑몰 SaaS (카페24, 고도몰, 아임웹, Shopify 등) | 상품 등록·다국어 번역, CS 자동 응대, 재고·발주 예측, 해외 결제·배송 연동 |
| **.ax erp** | 구독형 ERP, 엑셀 기반 관리 | 전표·문서 자동 입력, 보고서 자동 생성, 승인 흐름 자동화 |
| **.ax crm** | 구독형 CRM, 상담 툴 | 고객 자동 분류, 상담 요약, 후속 연락 자동화 |
| **.ax edu** | LMS, 강의 플랫폼 SaaS | 학습자 질의 응대, 학습 콘텐츠 생성, 수강·수료 관리 자동화 |

**우선 공략 대상 신호**
- 사업에 필요한 업무를 SaaS 밖(엑셀·수작업)에서 처리하고 있다
- 원하는 기능을 플랫폼이 지원하지 않아 앱·외주로 덧대고 있다
- 여러 SaaS 간 데이터를 손으로 옮기고 있다
- 판매 채널·사업 모델(도매, 해외, 공동구매, 맞춤 제작)이 늘고 있다

## 4. 상품 구조

```
.ax = 초기 전환비 + 월 구독료 (약정 24·36개월)
      약정 종료 → 소스코드·시스템 소유권 고객 이전
```

| 구성 | 포함 내용 |
|---|---|
| 초기 전환비 | 전환 진단, 시스템 설계, 구축, 데이터 이관(회원·주문·상품·콘텐츠), SEO 리디렉션, 병행 운영 |
| 월 구독료 | **매월 기능 확장(개발 시간)**, AI 업무 추가·고도화, 호스팅·인프라, 유지보수·장애 대응, 보안 업데이트 |

> 월 구독의 의미는 유지보수비가 아니라 **"우리 회사 전담 개발·AX 팀을 구독하는 것"**이다. 확장이 기본값.
| 약정 종료 시 | 소스코드·DB·인프라 고객사 제공. 이후 운영 여부·조건은 **약정 종료 시점에 별도 협의** |

## 5. 가격 (사이트 공개)

| 티어 | 대상 규모 | 초기 전환비 | 월 구독료 | 월 개선 시간 | AI 자동화 범위 |
|---|---|---|---|---|---|
| **Start** | 소규모, 단일 업무 | 990만원 | 월 99만원부터 | 8h | 핵심 업무 1개 |
| **Grow** | 성장 단계, 다수 업무 | 1,990만원 | 월 199만원부터 | 20h | 업무 3개 |
| **Scale** | 다수 시스템 통합 | 3,900만원부터 | 월 390만원부터 | 40h | 맞춤 설계 |

> ⚠️ 위 금액은 레이아웃·계산기 개발용 **더미 숫자**. 런칭 전 확정 필요. (VAT 별도 표기 예정)

- 공개 위치: "AX전환?" 페이지 가격 섹션 (메인에는 노출하지 않음)
- 공개 방식: "월 OO만원부터" + "정확한 금액은 업무 진단 후 확정"
- 36개월 약정 시 초기 전환비 50% 할인 (더미 조건)
- 비용 비교 계산기는 **사용하지 않음** (영업 논리가 비용이 아니므로)

## 6. 차별점 ("결국 또 구독 아닌가?"에 대한 답)

| | 기존 SaaS | .ax |
|---|---|---|
| 시스템 | 모두가 쓰는 같은 템플릿 | 우리 회사 전용 |
| 데이터 | 플랫폼에 묶임 | 고객 소유 |
| 소스코드 | 없음 | **약정 종료 시 고객사에 제공** |
| 업무 방식 | 플랫폼 구조에 사업을 맞춤 | **시스템을 사업에 맞춤** |
| 기능 추가 | 앱 구매, 외주, 또는 불가 | **매월 확장이 구독에 포함** |
| 여러 채널·사업 모델 | SaaS 여러 개를 이어 붙임 | 하나의 시스템으로 통합 |
| AI | 플랫폼이 주는 기능만 | 우리 업무 흐름 안에 설계 |

**대표 영업 문장:** "사업이 커지면, 시스템도 같이 커집니다." / 보조: "구독이 끝나면, 시스템은 고객님 것입니다." (소유권 = 통제권)

## 7. 전환 프로세스

1. **무료 업무 진단** — 지금 SaaS에서 안 쓰는 기능, SaaS 밖에서 덧대는 업무, 끊긴 데이터를 찾는다 → "우리 회사 메뉴" 초안 + AI가 맡을 업무 리포트
2. **설계** — 업무 흐름 기준 시스템·AI 자동화 설계, 티어 확정
3. **구축** — 자체 시스템 + AI 업무 자동화 개발
4. **이관** — 회원·주문·상품·콘텐츠 데이터, 결제(PG), 도메인, SEO 리디렉션
5. **병행 운영** — 기존 SaaS와 일정 기간 병행, 무중단 전환
6. **운영·개선** — 월 구독으로 유지보수 + 기능 개선 + AI 고도화
7. **소유권 이전** — 약정 종료 시 소스코드·시스템 제공

## 8. 영업 퍼널

```
사이트 방문 → 분야 확인 → 무료 업무 진단 신청
→ 진단 미팅 ("지금 메뉴 vs 우리 회사 메뉴" + AI 담당 업무 제시) → 티어 제안 → 계약
```

- 영업이 이겨야 할 상대는 경쟁사가 아니라 **"그냥 지금 SaaS 계속 쓰지"라는 관성**
- 무기: ① 고객 업무를 정확히 아는 진단("엑셀로 하던 그 일") ② 무중단 이전 경험 ③ 매월 확장되는 구독 ④ 소유권 이전
