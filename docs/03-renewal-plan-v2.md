# 리뉴얼 재기획 v2: 비즈니스 판단과 새 메인 컨셉

> 상태: 제안 · [01(서비스 정의)](./01-ax-service.md), [02(사이트 기획)](./02-site-plan.md)를 바탕으로 다시 판단한 내용
> 전제: 01·02의 피봇 방향(확장성, .ax 구독, 소유권 이전)은 유지한다. 바꾸는 것은 **누구에게 먼저 팔지, 무엇으로 믿게 할지, 메인을 어떻게 보여줄지**다.

## 1. 비즈니스 판단

### 1-1. 방향은 맞다. 다만 "AX"는 고객의 말이 아니다

- 성장 기업 대표는 "AX 전환"을 검색하지 않는다. "카페24 도매 단가", "공동구매 정산 엑셀", "쇼핑몰 ERP 연동"을 검색한다.
- 그래서 **.ax는 상품 이름으로만 쓰고, 설명은 고객의 업무 언어로** 한다.
  - 나쁨: "AX 전환으로 업무를 혁신합니다"
  - 좋음: "엑셀로 하던 도매 단가 관리, 시스템 안으로 들어옵니다"
- 메뉴 이름 "AX전환?"은 유지하되, 페이지 첫 문장은 고객 상황으로 시작한다.

### 1-2. 첫 고객층을 한 줄로 좁힌다 (제안)

4개 분야를 동시에 파는 건 사례가 쌓인 뒤의 일이다. 첫 6~12개월은 하나만 판다.

**제안 ICP: 소매와 도매(B2B)를 같이 하는, 쇼핑몰 SaaS를 쓰는 브랜드**
- 연 매출 30억~300억, 운영 인원 5~50명
- 신호: 거래처별 단가를 엑셀로 관리, 도매 주문을 메신저로 받음, 채널별 재고를 손으로 맞춤
- 이유: "SaaS에 없는 기능"이 가장 선명하고, 매일 반복되며, AI가 맡을 업무(주문 입력, 단가 적용, 재고 예측)가 바로 보인다.

공동구매·해외 판매·맞춤 제작은 같은 문법의 2순위 세그먼트로 둔다.

### 1-3. 진짜 경쟁자는 "관성"과 "작은 회사에 대한 불안"

고객이 망설이는 이유는 가격보다 이 두 가지다.

| 불안 | 지금 기획의 답 | 보강 제안 |
|---|---|---|
| 옮기다 매출이 멈추면? | 병행 운영, 무중단 이전 | 이전 체크리스트를 사이트에 공개 (PG, 회원 비밀번호, SEO 리디렉션) |
| 작은 회사인데 사라지면? | 약정 종료 후 소스 제공 | **계약 첫날부터 고객사 저장소에 코드를 올린다** (읽기 권한). 소유권 이전이 "약속"이 아니라 "현재 상태"가 된다 |
| 결국 또 구독 아닌가? | 매월 확장 포함 | 매월 "이번 달 추가된 기능" 리포트를 표준 산출물로 |

> 결정 필요: "첫날부터 코드 공개"는 영업 무기로 강하지만 계약·보안 조건 정리가 필요하다.

### 1-4. 가격 구조 점검 (더미 기준)

| 티어 | 24개월 총액 | 판단 |
|---|---|---|
| Start | 990 + 99×24 = 약 3,370만원 | 월 8h는 기능 확장이라 부르기 어렵다. 진입 상품으로 두되 "AI 업무 1개 + 유지"로 정직하게 설명 |
| Grow | 1,990 + 199×24 = 약 6,770만원 | 실제 주력. 사이트에서 "가장 많이 선택"으로 기준점 역할 |
| Scale | 3,900 + 390×24 = 약 1억 3,260만원~ | 견적형. 금액보다 "전담 팀" 구성을 보여준다 |

- 36개월 약정 시 전환비 50% 할인은 유지 (락인 대신 소유권으로 상쇄되므로 거부감이 적다)
- 계산기 없음 원칙 유지

### 1-5. 사례가 없다는 문제가 가장 크다

포트폴리오의 AX 탭을 기본으로 크게 보여주려면 사례가 있어야 한다.

- **파일럿 3사 프로그램**: 기존 웹에이전시 고객 중 SaaS를 쓰는 곳 3곳에 전환비 할인 + 사례 공개 동의 조건으로 제안
- 사례가 나오기 전까지 AX 탭은 "진단 사례"(가상 아닌 실제 진단 결과, 회사명 비공개)로 채운다
- 결과 숫자는 하나만: "SaaS 밖에서 하던 업무 n개 → 시스템 안으로"

### 1-6. 무료 진단의 산출물을 눈에 보이게

진단 신청이 KPI라면, "신청하면 무엇을 받는지"가 메인 다음으로 중요하다.

- 진단 결과물 = **"우리 회사 메뉴" 1장 + AI가 맡을 업무 목록 + 이전 리스크 체크**
- 문의 폼에서 고객이 적은 "엑셀로 하는 일"이 그대로 진단 결과물의 재료가 된다

## 2. 메인 디자인: 새 컨셉

### 2-1. 지난 시안에서 배운 것

- 메시지(범용 → 맞춤)는 맞았다. 문제는 **표현 매체**였다. 목록·구분선·2단 배치는 문서의 문법이다.
- 웹만이 가진 문법을 쓴다: **상자(frame), 넘침(overflow), 다시 흐름(reflow), 스크롤, 커서.**
- 금지 유지: 노드 그래프, 빛, 파티클, 신경망, 보라 그라데이션, 비용 중심 은유.

### 2-2. 컨셉 후보

#### A. 넘치는 글자 (추천)

**한 줄 요약:** 사업은 커다란 글자이고, SaaS는 정해진 크기의 상자다. 글자가 커지면 상자에서 넘치고 잘린다. 시스템을 다시 지으면 상자가 글자에 맞춰 다시 그려진다.

```
[1] 정해진 상자 안에 회사 업무가 꽉 차 있다
┌──────────────────────────────┐
│ 상품관리  주문관리  회원관리      │
│ 게시판  쿠폰  적립금  배너 ...    │   ← 범용 SaaS 관리자 화면 크기의 회색 틀
└──────────────────────────────┘

[2] 스크롤 = 사업 성장. 업무 글자가 커지고 늘어난다
┌──────────────────────────────┐
│ 도매 거래처별 단가  공동구매 정│산      ← 틀 밖으로 넘친 부분은 잘려서 안 보인다
│ 채널별 재고 통합  맞춤 제작 주│문      (overflow:hidden 그대로)
└──────────────────────────────┘
     엑셀  엑셀  엑셀                ← 넘친 업무가 틀 아래로 떨어져 엑셀 칸에 쌓인다

[3] 틀이 지워지고, 글자 모양대로 새 틀이 그려진다
 ┌─────────────────┐┌───────┐
 │●도매 거래처별 단가 ││●공동구매│      ← 업무 하나하나에 꼭 맞는 칸
 └─────────────────┘└───────┘      ● 빨간 점 = AI가 맡는 업무
 ┌──────────┐┌─────────────┐
 │채널별 재고 ││●맞춤 제작 주문 │
 └──────────┘└─────────────┘

[4] 마지막 화면
   사업이 커지면, 시스템도 같이 커집니다.     (거대한 타이포)
   .ax commerce        [업무 진단 신청하기]
```

- 왜 이것인가: 브라우저의 상자·넘침·재배치는 웹에서만 성립하는 표현이다. 문서처럼 보일 수 없다.
- 대담함: 화면 높이를 꽉 채우는 타이포가 실제로 잘리고, 밀리고, 다시 맞춰진다. 글자가 곧 그림이다.
- 인터랙션: 스크롤로 진행(한 섹션을 고정, 약 2.5화면 분량). 데스크톱에서는 틀 모서리를 끌어 늘려볼 수 있지만, 늘려도 사업 글자가 더 빨리 커져 끝내 넘친다.
- 빨간 점의 역할 하나: 로고의 점 → 틀을 다시 그리는 펜 끝 → AI 업무 표시 → `.ax`의 점.
- 리스크: 스크롤 고정 연출이 길면 지루하다. 전체 3초 자동 재생 + 스크롤로 되감기 가능한 방식이 대안.

#### B. 분해 조립도

**한 줄 요약:** 실제처럼 보이는 범용 쇼핑몰 관리자 화면을 건축 분해도처럼 층별로 띄운다. 안 쓰는 층은 회색으로 빠지고, 엑셀 시트가 옆에서 끼워진 뒤, 우리 회사 구조로 다시 쌓인다.

```
        ╱ 메뉴 층 ╱        ← 회색으로 빠져나감
      ╱ 화면 층 ╱
    ╱ 데이터 층 ╱  ◀ 엑셀 시트가 옆에서 끼워짐
  ╱ AI 업무 층 ●╱          ← 빨간 점이 찍힌 새 층
```

- 장점: "다시 짓는다"는 말과 가장 잘 맞는다. 공간감이 크다.
- 리스크: 3D 기울임은 흔한 "테크 랜딩" 그림이 되기 쉽고, 구현 비용이 크다.

#### C. 방문자가 직접 적는 메인 (A에 붙이는 2차 기능)

메인 마지막 화면에 입력칸 하나: "지금 엑셀로 하는 일 하나만 적어보세요." 적은 글자가 A의 새 틀 안에 칸으로 들어가고, 진단 신청 폼에 그대로 채워진다. 전환율 실험용.

### 2-3. 디자인 토큰 (A 기준)

| 이름 | 값 | 쓰임 |
|---|---|---|
| 종이 | `#FFFFFF` | 배경 |
| 먹 | `#000000` | 글자, 새 틀 |
| 인주 | `#D82E28` | 점 하나: 로고, 펜 끝, AI 업무 표시 |
| 꺼진 기능 | `#C4C4C4` | SaaS 틀, 안 쓰는 기능 |
| 엑셀 칸 | `#E9E9E9` 칸 + `#C4C4C4` 1px 격자 | 넘친 업무가 쌓이는 곳 (초록 엑셀색은 쓰지 않음) |

- 서체: Wanted Sans Variable 한 계열. 굵기 축(400~1000)을 연출에 직접 쓴다. 업무 글자는 커질수록 굵어진다.
- 정렬: 왼쪽 정렬, 마지막 타이포만 화면 폭 기준으로 크게.
- 지켜온 금지 목록([02 문서 2장](./02-site-plan.md#2-디자인-원칙)) 그대로 유지.
